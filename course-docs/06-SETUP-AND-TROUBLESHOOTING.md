# 06 — Setup and troubleshooting

Each app is independent. From either `completed/` or `starter/`, run `npm install`, `npm run dev`, and open the local URL Vite prints. `npm run build`, `npm run test` and `npm run lint` are available in the completed app.

WebMCP is progressive enhancement: the storefront remains usable when `document.modelContext` is missing. Chrome's current developer documentation says to enable `chrome://flags/#enable-webmcp-testing` and relaunch for local development, or use the Chrome 149 origin trial instructions. The API is experimental and this does not promise support in another browser, a standard Chrome release, or a specific agent client. Use HTTPS or localhost because the API is secure-context only.

On `/dev-tools`, select a tool, edit its JSON input, and click Execute function. The panel directly invokes validated app functions even if the API is absent. Check the status indicator for API detection; API detection alone does not establish agent connectivity. For actual discovery, use a compatible WebMCP browser agent or inspector extension, visit the app directly, and confirm it lists the six tool names. Follow the extension's own model/key setup; never put secrets in this demo.

The optional bundled Python agent can be run with the steps in the root README. It needs an OpenAI API key and API access, Python packages from `agent/requirements.txt`, and a dedicated persistent Chrome profile started with CDP port 9222. Copy `agent/.env.example` to `agent/.env` and set `OPENAI_API_KEY`; this file is git-ignored. ChatGPT and API billing are separate. Enable Chrome's WebMCP testing flag once in the dedicated profile. On later runs, launch the same profile with the same `--user-data-dir` and `--remote-debugging-port=9222`; the flag is profile-persistent, while the debugging port must be passed at launch. The Gradio chat at `http://127.0.0.1:7860` can be opened in a separate regular browser window. If the agent says it cannot connect to Chrome, check `http://127.0.0.1:9222/json/version`; if it reports no tools, check the WebMCP flag in the connected profile and confirm the completed app loaded. If the model request fails, check the API key, model name, and API project access. Environment settings include `OPENAI_MODEL`, `CHROME_CDP_URL`, and `SIMPLISHOP_URL`.

Common issues: unsupported API means use the workbench; registration failure can indicate missing flag, an insecure context, a disabled `tools` permissions policy, or duplicate page registration; invalid JSON/arguments appear in the workbench error area; stale local changes can be fixed by reloading. If npm cannot reach the registry, installation is blocked by network access and must be retried where npm registry access is available.
